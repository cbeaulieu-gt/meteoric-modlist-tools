# Design notes

These are the internal design documents written while building the tools in this
repository, preserved because they explain *why* things work the way they do —
the mod-matching waterfall, version cleaning, the coverage state model, the
name-case rules, the report naming convention.

They are **not** user documentation and are not maintained as such. They describe
the state of the design at the time each feature was built, and they discuss the
real modlists they were developed against. For how to actually use the tools, see
the [README](../../README.md).

`design/` holds the specs — what was being built and why. `plans/` holds the
matching implementation plans. Not every spec has a plan.
